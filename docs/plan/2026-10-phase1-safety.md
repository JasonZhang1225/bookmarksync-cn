## 阶段目标

让应用达到“可以放心在日常浏览器配置上开启写入”的程度。优先级依次为：

1. **不丢数据**：任何异常都不能被解释成大量删除，并扩散到所有设备。
2. **不误合并**：不同网页不能被当作同一个书签。
3. **不制造重复和循环**：同一份书签不能反复写入，也不能越写越多。

改书签身份模型、做浏览器扩展这类大改动不在本阶段动手，只出设计文档（见 D 类条目）。

## 条目详情

### S1 空读取或结构异常被当作“全部删除”（P0）

- **现象**：`SafariParser.read()` 在 plist 缺少 `Children`，或找不到对应的配置文件夹时返回 `[]` 而不是抛错。`FirefoxParser.read()` 复制数据库时用 `try?`，复制失败或者复制到不一致的快照，也可能读出空结果或残缺结果。引擎在导入阶段把“上次有、这次没有”统统当成删除（`SyncEngine+Execute.swift:237` 起）。
- **后果**：一次读取异常，就会把这个配置的全部书签从中枢删掉，再写到所有其他浏览器，最后经云同步扩散到所有设备。
- **修复思路**：
  1. 解析器层：结构不符合预期时抛出明确错误（新增 `BookmarkParseError`），不再返回 `[]`。Firefox 的复制失败要抛错，不能吞掉。
  2. 引擎层兜底：上次观察到的状态非空、这次读到空，或者丢失比例超过阈值时，本轮跳过该配置的导入，**也不更新它的 `observedStateData`**，并在界面上提示。
  3. 读取失败的配置在本轮也不参与导出（避免对着一个读不出来的文件写入）。
- **验收**：新增测试：Safari plist 缺少 `Children` / 缺少配置文件夹时抛错；上次非空、这次为空时中枢不变、其他浏览器不收到删除；`observedStateData` 不被覆盖。
- **实现（`fix/s1-s2-deletion-safety`）**：新增 `BookmarkParseError`；Safari 缺少 `Children`、默认配置没有 BookmarksBar/BookmarksMenu、找不到命名配置文件夹时抛错；Firefox 数据库复制失败、缺少工具栏（3）或“其他书签”（5）根目录时抛错。引擎层的“上次非空、这次为空”由 S2 的 `DeletionGuard` 以 `emptyRead` 原因暂停。
- **未做**：解析失败目前只写日志，菜单栏没有提示；留到 U1 一起做。

### S2 大批量删除保护（P0）

- **现象**：`DESIGN.md` 第 8 节写明“大量删除时延迟应用并提醒用户”，代码中没有实现。
- **修复思路**：导入阶段统计每个配置本轮的删除数，超过阈值（例如同时满足 ≥10 条且 ≥20%，具体数值在实现时用测试确定）时：本轮不应用这些删除，把这个同步组标记为“等待确认”，在菜单栏显示“某浏览器删除了 N 项，[应用] [忽略并恢复]”。确认前该同步组不向任何浏览器写入。
- **验收**：测试覆盖阈值以下正常传播、阈值以上暂停、确认后传播、拒绝后恢复。
- **实现（`fix/s1-s2-deletion-safety`）**：
  - `BookmarkSync/Core/DeletionGuard.swift`：满足任一条件即暂停——读到空结果而上次非空；删除 ≥10 个且 ≥20%；删除 ≥3 个且 ≥50%。用户已确认过的删除不再计入。
  - **决策**：只冻结出问题的那个浏览器配置（本轮不从它导入、不向它写入、不更新它的上次观察状态），同组其他浏览器照常同步。原因：中枢里这些书签还在，其他浏览器不受影响；冻结整个同步组会让无关的新增也停下来。
  - 被暂停的配置每轮都会重新检查；读取恢复正常后暂停自动解除。
  - 菜单栏顶部显示红色提示（`DeletionHoldBanner`），提供“确认删除”和“恢复书签”。恢复 = 中枢保持不变，把该浏览器当前文件作为新的观察基线，导出阶段再把缺失的书签写回。
  - 暂停状态只保存在内存里；应用重启后，由于观察基线没有更新，第一次同步会重新暂停。

### S3 Firefox 写入方式（P0）

- **现象**：`write()` 先递归删除工具栏（3）和“其他书签”（5）下的全部记录，再按中枢重建，每条记录生成随机新 GUID（`FirefoxParser.swift:238-297`）。读取时跳过了分隔线，重建时也不会写回，所以分隔线会丢失。没有写 `moz_bookmarks_deleted`，也没有维护 `syncStatus` / `syncChangeCounter`。
- **后果**：在 Firefox Sync 看来，每次写入都等于“删除全部书签，再新建一批”，可能产生重复、已删除的书签又被恢复、其他设备上的书签被清空等情况；书签的关键字、标签等附加数据也会丢失。
- **修复思路**：改成增量写入：按 GUID（找不到时按父级 + 网址）把中枢节点和现有记录对应起来，只做新增、修改、移动、删除；已存在的记录保留原 GUID；删除时按 Firefox 的规则写入删除记录并更新同步计数；跳过分隔线等不认识的记录，不删除它们。根目录改用固定 GUID（`toolbar_____`、`unfiled_____`、`menu________`、`mobile______`）识别，不写死数字 ID。
- **验收**：用 fixture `places.sqlite` 测试：未改动的书签 GUID 不变；分隔线、标签保留；删除产生删除记录；重复写入同一份中枢状态后数据库无变化（幂等）。还需要用测试账号做一次 Firefox Sync 往返实测。

### S4 Firefox“书签菜单”被复制（P0，待确认）

- **现象**：读取时 `getPath` 把 ID 1/2/4 都当作 `other`（`FirefoxParser.swift:87`），因此“书签菜单”（2）下的书签以 `other:` 开头、`parentId` 为空，也就是被视为“其他书签”的根级条目。写入时只清空 3 和 5，再把 `other` 的内容插进 5。结果是菜单里的原条目还在，5 下面又多了一份；下次读取时同一个 ID 出现两次，第二份变成 `:dup1`。
- **修复思路**：先写测试确认这个现象；再决定“书签菜单”是独立映射（和 Safari 的 BookmarksMenu 对应），还是明确只读、不参与同步（见 M2）。
- **验收**：含“书签菜单”条目的 fixture 写入两次后，总条目数不变。

### M1 网址匹配过于激进（P1）

- **现象**：`normalizeURL` 去掉协议和 `www.`，这属于有意为之；但它同时忽略端口，并把路径、查询参数、锚点都转成小写。`localhost:3000` 和 `localhost:8080`、`/Docs/A` 和 `/docs/a`、`?id=AbC` 和 `?id=abc` 都会被当作同一个书签。
- **修复思路**：只把协议和主机名转成小写；保留非默认端口；路径、查询参数、锚点保持原样大小写；结尾斜杠和 `www.` 的处理保持不变。同时修正 README 中“去掉查询参数”的错误描述（E1）。
- **⚠ 迁移要求**：这会改变书签 ID。必须在同一个 PR 里，对中枢 `BookmarkNode.id` / `parentId` 和每个配置的 `observedStateData` 做一次性重新计算（带版本号，迁移失败时整体回退、不同步），否则升级后第一次同步会出现“全部删除 + 全部新增”。
- **验收**：规范化单元测试覆盖端口、大小写、查询参数；迁移测试：旧版本数据库升级后，第一次同步不产生任何新增或删除。

### M2 根目录映射不一致（P1）

- **现象**：
  - Chrome 有三个根目录：`bookmark_bar`、`other`、`synced`（移动设备书签）。Safari 写入时只写 `bookmark_bar` 和 `other`（`SafariParser+Write.swift:133-134`），Firefox 只写工具栏和“其他书签”。来自 Chrome“移动设备书签”的条目永远写不进 Safari 和 Firefox；导出阶段每轮都会发现“缺少”，于是每轮都排一次写入。iOS Chrome 新加的书签默认就在这里。
  - Safari 的非默认配置（Safari 17 及以后的多配置）把所有内容都映射到 `bookmark_bar`，`other` 下的书签同样写不进去。
  - Firefox 的“书签菜单”和“移动设备书签”没有映射（见 S4）。
- **修复思路**：定义一张统一的根目录映射表（写进 `DESIGN.md` 第 6 节的中文补充或计划附录）。目标浏览器没有对应根目录的条目要么映射到约定位置（例如 Safari 的 BookmarksMenu 下一个固定子文件夹），要么明确不同步；无论哪种，导出阶段都不能把这些条目算作“不一致”。
- **验收**：Chrome 移动设备书签存在时，Safari 和 Firefox 写入一次后，下一轮同步没有待写入项。

### M3 空文件夹被删除（P1）

- **现象**：中枢会过滤掉没有书签的文件夹（`SyncEngine+Execute.swift:326`）。导出阶段发现浏览器里有、中枢里没有，就记为删除（`:420-426`），连创建这个文件夹的浏览器也不例外。
- **修复思路**：空文件夹在中枢中保留，或者在导出比较时忽略空文件夹，不产生删除。
- **验收**：在一个浏览器中新建空文件夹，同步后它不会被删除（是否传播到其他浏览器另定）。

### M4 `:dupN` 后缀依赖顺序（P1，待评估）
